## 轮次 5 · 用户第二轮反馈（5 条，全部指向时间错位与接缝）

用户逐条指出：第 3 镜的打字声漏进第 2 镜尾部；2→3 衔接生硬；第 4 镜没打字却有打字声；3→4 生硬；第 5 镜前后半缺承接；第 9 镜前半没打字却有打字声。

### 根因：数组下标引用 TYPING

`shot-voice.js` 写 `TYPING[4]`、`shot-end.js` 写 `TYPING[5]`——都是**位置耦合**。
上一轮在第 3 镜插入「reject」那一行后，`TYPING` 从 8 项变成 9 项，索引整体后移：

| 文件 | 旧下标 | 指向谁 | 结果 |
|---|---|---|---|
| shot-voice | `TYPING[4]` | 第 3 镜的 reject 行 | 第 4 镜「没打字却有打字声」，字打在第 3 镜的时间段 |
| shot-end | `TYPING[5]` | 第 4 镜的 anima_speak | 第 9 镜「没打字却有打字声」 |

**这次一次灭掉三个症状里的两个。**

修法是根治而不是改数字：新增 `typing(shotId, line)` 按名字查找，五个 shot 文件全部改用它。
现在 `grep "TYPING\[[0-9]\]"` 零命中。

第三条（第 3 镜声音漏进第 2 镜）是另一个原因：第 3 镜第一行原本 `t0 = at('memory', -0.55)`
——我上一轮故意让它提前起打，好让切进来时画面已有字。加了转场之后不再需要抢跑，
改成 `+0.12`，并在 score 里加了硬门禁：

```js
// 击键只允许在自己的镜头拥有画面时发声
if (t < host.t0 || t >= host.t1) continue;
```

审计结果：362 个击键，dropped 0（全部落在各自镜头内）。

### 接缝：新增 transitions.js

原来每个镜头边界都是硬切，两个高密度 UI 直接对撞，所以「生硬」。
现在每个边界都有转场，由 `timeline.js` 的 `TRANSITIONS` 声明，画面与配乐共用：

| 边界 | 类型 | 为什么 |
|---|---|---|
| 1→2 | rise | 安装 → 控制中心：换了一种「表面」，新面板从底部升起 |
| 2→3 | iris | 仪表盘 → 编辑器：从内容中心开花，把注意力收进一行代码 |
| 3→4 | slide | 编辑器 → 编辑器：同类型屏幕，像 IDE 切标签页 |
| 4→5 | rise | 编辑器 → 日志：竖向换上下文 |
| 5→6 | slide | 日志 → QQ/终端 |
| 6→7 | slide | 你不在 → 模型链 |
| 7→8 | rise | 模型链 → 四分屏 |
| 8→9 | iris | 四分屏 → 结尾落版 |

**两个设计约束（都是踩了坑才定的）：**
1. **全屏 UI 不能 alpha 混合。** 两个高密度界面叠加 0.5 秒，两套代码和标签都同时可读，
   读起来像坏帧。所以 iris 是**遮罩**不是淡入，任何像素上只有一个镜头可读。
2. **缩放不能小于 1。** 第一版 iris 让进场面从 1.07 收到 1.0，但出场那一侧仍在画布内缩放，
   结果四周露出未渲染的边。现在进场侧 `s ∈ [1.0, 1.06]`，永远覆盖画布。

顺带删掉了各镜头自己的「开场缩放」（memory 1.045→1.0、chain 1.03→1.0、center 1.045），
否则等于进场动作做两遍，而且转场期间镜头还没归位 → 上一镜从边上透出来。

### 第 5 镜前后半的承接

原来日志 → 分屏是硬切，两半之间没有任何视觉关系。现在那行琥珀金日志在切点前 0.7 s
「升格」：日志窗口向上退、缩小、压暗让位，那行字自己浮到画面中线并拉出一条全宽细线，
**这条线就是随后分屏的接缝**。分屏不是凭空出现，是从这行日志里长出来的。
